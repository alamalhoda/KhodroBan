# بررسی تطابق SmartAssistantView.vue با استانداردهای پروژه

## خلاصه

**وضعیت فعلی:** فایل با استانداردهای پروژه همخوانی ندارد و بیشتر یک **مکاپ استاتیک** است تا یک View عملیاتی.

---

## استانداردهای پروژه (از vue-frontend-implementation.md و Viewهای دیگر)

| مورد | انتظار پروژه | مثال (مثلاً DashboardView) |
|------|----------------|-----------------------------|
| **Layout** | استفاده از `MainLayout.vue` (Sidebar + Header + slot) | `import MainLayout from '../components/MainLayout.vue'` و `<MainLayout>...</MainLayout>` |
| **جریان داده** | Component → Pinia Store → Service → Shared | `useDashboardStore()`, `useAuthStore()` |
| **متن‌های قابل ترجم** | استفاده از `vue-i18n` (`useI18n`, `t()`) | `const { t } = useI18n()` و `{{ t('key') }}` |
| **State چت** | استور مخصوص AI (مثلاً `ai.js` / `smartAssistant.js`) | مشابه `useDashboardStore()` |
| **ناوبری** | از طریق Sidebar مشترک؛ View فقط محتوای اصلی را رندر می‌کند | بدون sidebar تکراری داخل View |

---

## موارد عدم تطابق در SmartAssistantView.vue فعلی

### ۱. عدم استفاده از MainLayout

- **وضعیت:** View خودش یک Layout کامل (aside + main + header) دارد و Sidebar و Header را داخل خودش تکرار کرده است.
- **مشکل:** با بقیهٔ Viewها (مثل DashboardView، SettingsView) ناسازگار است و ناوبری و ظاهر یکپارچهٔ اپ را خراب می‌کند.
- **توصیه:** کل محتوای صفحه داخل `<MainLayout>` قرار بگیرد و فقط ناحیهٔ چت (هدر داخلی چت، لیست پیام‌ها، نوار ورودی) داخل View باشد.

### ۲. اسکریپت خالی

- **وضعیت:** بلوک `<script setup>` عملاً خالی است.
- **مشکل:** هیچ state، store، یا هندلری برای ارسال/دریافت پیام وجود ندارد.
- **توصیه:** استفاده از استور Smart Assistant (مثلاً `useSmartAssistantStore()` از `stores/smartAssistant.js`) و متصل کردن به `aiService`؛ مدیریت `userInput`، `messages`، `isLoading` و ارسال پیام از طریق استور.

### ۳. محتوای کاملاً استاتیک

- **وضعیت:** همهٔ پیام‌ها، نام کاربر، خودروی انتخاب‌شده و چپ‌های پیشنهادی ثابت و هاردکد هستند.
- **مشکل:** چت واقعی کار نمی‌کند و برای تست و توسعهٔ بعدی مناسب نیست.
- **توصیه:** لیست پیام‌ها از استور (مثلاً `messages`) با `v-for` رندر شود؛ پیام خوش‌آمد و پاسخ‌ها از همان منبع بیاید؛ در صورت وجود، نام کاربر و خودروی انتخاب‌شده از auth/vehicle store یا props بیاید.

### ۴. عدم استفاده از vue-i18n

- **وضعیت:** تمام متن‌های فارسی به‌صورت مستقیم در قالب نوشته شده‌اند.
- **مشکل:** چندزبانگی و نگهداری متن‌ها سخت می‌شود و با بقیهٔ پروژه یکسان نیست.
- **توصیه:** متن‌های قابل نمایش به کاربر (عنوان‌ها، دکمه‌ها، placeholder، پیام خطا و غیره) با `t('key')` از i18n بیاید و کلیدها در `locales/fa.json` (و در صورت نیاز en/ar) تعریف شوند.

### ۵. ناوبری تکراری و بدون router-link

- **وضعیت:** داخل View یک sidebar با لینک‌های `href="#"` وجود دارد.
- **مشکل:** با Sidebar و Router مشترک پروژه هماهنگ نیست و برای SPA درست کار نمی‌کند.
- **توصیه:** این sidebar حذف شود و ناوبری فقط از طریق `MainLayout` و `Sidebar.vue` انجام شود؛ در Sidebar یک `router-link` به `/smart-assistant` اضافه شود (در صورت نبود).

### ۶. عدم پشتیبانی عملی از Dark Mode

- **وضعیت:** برخی کلاس‌ها از توکن‌های طراحی پروژه استفاده می‌کنند (مثل `text-text-main`) ولی بخش‌های زیادی فقط رنگ‌های ثابت (مثل `bg-gray-100`, `text-gray-700`) دارند.
- **توصیه:** برای بخش‌های چت و کارت‌ها از توکن‌های مشترک و کلاس‌های `dark:` استفاده شود تا با بقیهٔ اپ و حالت تاریک هماهنگ باشد.

### ۷. دسترس‌پذیری (a11y)

- **وضعیت:** برای آواتارها `data-alt` استفاده شده که خوب است؛ ولی ناحیهٔ چت و پیام‌های جدید بدون نقش/برچسب مناسب برای screen reader هستند.
- **توصیه:** ناحیهٔ لیست پیام‌ها با نقش مناسب (مثلاً `role="log"` یا `region` با `aria-label`) و در صورت نیاز `aria-live` برای پیام‌های جدید؛ دکمه‌ها و فیلد ورودی با `aria-label` یا متن مرئی.

## کارهای پیشنهادی برای هماهنگ‌سازی با استانداردها

1. **استفاده از MainLayout**  
   View را طوری بازنویسی کنید که فقط محتوای اصلی چت (هدر چت، لیست پیام، نوار ورودی) داخل `<MainLayout>` باشد و sidebar/header کلی از MainLayout بیاید.

2. **اضافه/استفاده از استور Smart Assistant**  
   در صورت نبود، استور (مثلاً `stores/smartAssistant.js`) با stateهای `messages`, `isLoading`, `error` و اکشن `sendMessage` ایجاد شود و در View از آن استفاده شود (و در صورت وجود از همان استور فعلی استفاده شود).

3. **اتصال به aiService**  
   در استور، ارسال پیام با `aiService.analyzeCarIssue` (یا تابع معادل) انجام شود و پاسخ در `messages` قرار بگیرد.

4. **داینامیک کردن محتوا**  
   پیام‌ها با `v-for` روی `messages` از استور؛ نمایش وضعیت تایپ (loading) و خطا؛ در صورت وجود، نام کاربر و خودرو از auth/vehicle store.

5. **اضافه کردن i18n**  
   کلیدهای لازم برای این View در `locales/fa.json` (و در صورت نیاز en/ar) تعریف و در قالب با `t('key')` استفاده شوند.

6. **حذف sidebar تکراری**  
   ناوبری فقط از Sidebar مشترک؛ در `Sidebar.vue` لینک به `/smart-assistant` با متن مناسب (مثلاً «مشاور هوشمند») اضافه شود.

7. **یکنواخت کردن استایل با Dark Mode**  
   استفاده از توکن‌های طراحی و کلاس‌های `dark:` برای پس‌زمینه و متن ناحیهٔ چت و کارت‌ها.

8. **بهبود a11y**  
   نقش و برچسب برای ناحیهٔ چت و اعلان پیام جدید؛ برچسب برای دکمه‌ها و textarea.

---

## جمع‌بندی

با تغییرات بالا، SmartAssistantView.vue با استانداردهای پروژه (Layout مشترک، Pinia، i18n، جریان داده از طریق استور و سرویس) هماهنگ می‌شود و هم برای ادغام با برنچ و هم برای توسعهٔ بعدی (اتصال به backend واقعی، Gemini و غیره) مناسب خواهد بود.
