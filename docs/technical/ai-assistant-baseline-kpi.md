# Baseline و KPIهای مهاجرت دستیار هوشمند (AI Assistant)

این سند سناریوهای تست دستی، نمونه‌های request/response و KPIهای مهاجرت از مسیر فعلی (Supabase/فرانت) به backend-first Django را ثبت می‌کند.

**آخرین به‌روزرسانی:** 2026-02-16

---

## 1. سناریوهای تست دستی (حداقل ۵ سناریو)

| # | سناریو | ورودی نمونه | خروجی مورد انتظار | وضعیت |
|---|--------|-------------|-------------------|--------|
| 1 | سوال عمومی درباره تعویض روغن | «هر چند کیلومتر روغن عوض کنم؟» | پاسخ فارسی درباره بازه تعویض روغن (مثلاً ۵۰۰۰–۱۰۰۰۰ km) | ثبت شده |
| 2 | سوال با context خودرو | با یک خودرو ثبت‌شده: «بر اساس کیلومتر فعلی خودمون کی باید سرویس بعدی باشه؟» | پاسخ با در نظر گرفتن currentKm و پیشنهاد بازه | ثبت شده |
| 3 | چند پیام پشت‌سرهم (history) | پیام ۱: «پژو ۲۰۶ دارم»؛ پیام ۲: «کی روغن عوض کنم؟» | پاسخ با ارجاع به پژو ۲۰۶ | ثبت شده |
| 4 | خطای شبکه / timeout | قطع اینترنت یا timeout مصنوعی | پیام خطای قابل فهم و امکان retry | ثبت شده |
| 5 | پیام خالی یا خیلی کوتاه | «» یا «ا» | عدم ارسال یا validation و پیام راهنما | ثبت شده |

## 2. نمونه Request/Response (مسیر فعلی)

نمونه payload ارسالی از فرانت به `analyzeCarIssue` (shared AI):

```json
{
  "prompt": "هر چند کیلومتر روغن عوض کنم؟",
  "mode": "fast",
  "userContext": {
    "vehicles": [{"id": "...", "model": "پژو ۲۰۶", "year": 1400, "plateNumber": "12ج34567", "currentKm": 80000}],
    "recentServices": [],
    "recentExpenses": []
  },
  "conversationContext": {
    "messages": [{"role": "user", "text": "..."}, {"role": "model", "text": "..."}],
    "maxHistoryMessages": 10
  }
}
```

نمونه پاسخ (ساختار `AIResponse` در shared):

```json
{
  "text": "معمولاً هر ۵۰۰۰ تا ۱۰۰۰۰ کیلومتر...",
  "groundingChunks": [],
  "metadata": { "model": "gpt-3.5-turbo", "usage": {...}, "provider": "openai" }
}
```

## 3. KPIهای مهاجرت

| KPI | تعریف | هدف پس از مهاجرت |
|-----|--------|-------------------|
| **p50 latency** | میانه زمان پاسخ (از ارسال پیام تا دریافت متن assistant) | ≤ مقدار baseline یا حداکثر +۲۰٪ |
| **p95 latency** | صدک ۹۵ زمان پاسخ | ≤ مقدار baseline یا حداکثر +۳۰٪ |
| **error rate** | نسبت درخواست‌های منجر به خطای ۴xx/۵xx به کل درخواست‌ها | ≤ baseline؛ ترجیحاً کمتر |
| **timeout rate** | نسبت درخواست‌های timeout شده | ≤ baseline |
| **fallback rate** | در صورت تعریف fallback (مثلاً provider جایگزین)، نسبت استفاده | قابل اندازه‌گیری و گزارش |

**نحوه اندازه‌گیری:** لاگ‌های ساختاریافته در backend (request_id, latency_ms, status) و در صورت نیاز ابزار مانیتورینگ.

## 4. یادداشت برای رگرسیون

- قبل از cutover نهایی، همین سناریوها روی endpoint جدید Django اجرا شوند.
- در صورت تفاوت کیفیت پاسخ (به‌دلیل تفاوت system prompt یا context)، در Context Builder تنظیم شود.
